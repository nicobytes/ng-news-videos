Hola, mi nombre es Ricardo Chavarría y esto es NG News

en español con las últimas novedades de la comunidad de Angular.

PrimeNG, la popular librería de componentes de interfaz de usuario,

anunció que sus futuras versiones principales

ya no estarán disponibles como código abierto,

salvo a través de una licencia comunitaria gratuita

para personas individuales, estudiantes,

organizaciones sin fines de lucro,

proyectos open source no comerciales y pequeñas empresas.

Esto no solo aplica a la versión de Angular, sino también a la de React y Vue.

La razón es que la librería ha crecido con el tiempo,

lo que exige dedicarle mucho más trabajo.

Y en cierto punto, los ingresos generados por la venta

de productos complementarios ya no cubrían los costos de desarrollo.

La nueva marca comercial es PrimeUI.

El precio de lanzamiento fue de $599 por desarrollador.

Una licencia perpetua para las versiones cubiertas

que incluye un año de actualizaciones.

También da acceso a PrimeUI Pro,

que incluye componentes avanzados para gráficos,

editor de texto, planificador, tablero de tareas y más.

Estos componentes Pro no forman parte de la licencia comunitaria.

Ante esto, OpenNG, que se dedica a mantener librerías abandonadas,

anunció que PrimeNG cerró su código.

El repositorio oficial de GitHub fue archivado

el 28 de junio de 2026 y OpenNG creó

una copia del proyecto regenerando issues y pull requests pendientes.

Su objetivo es lanzar una versión beta compatible con Angular 22 para este fork.

Por el momento, el nombre definitivo no está cerrado, ya que OpenNG busca evitar

similitudes con PrimeNG debido a los planes de registro de la marca PrimeTek.

Devin Chasanoff del equipo de Angular publicó

un artículo sobre cómo usar A2UI con Angular,

lo que permite crear interfaces dinámicas controladas

por el modelo de inteligencia artificial.

El usuario expresa una intención a través del frontend

y este envía dicha intención junto con el contexto relevante a un modelo.

Esta comunicación puede incluir además de un catálogo

de componentes que el frontend sabe renderizar.

El modelo decide si necesitan componentes visuales,

cuáles son los más adecuados y devuelve

instrucciones estructuradas a la aplicación.

A2UI es el protocolo utilizado para estos casos

de uso de interfaces generadas por agentes.

En otras noticias, ha comenzado el trabajo

para integrar el comportamiento de resource con router.

Apareció un pull request para uso interno

que utiliza un comportamiento de tipo snapshot

en el routerResource para incorporar información específica de navegación.

Ese snapshot congelaría el estado del recurso,

por ejemplo, su valor, mientras ocurre la navegación.

Una vez que la navegación se completa con éxito, el nuevo valor queda expuesto.

Si se cancela, el valor congelado permanece durante la recuperación.

Imaginen el caso habitual sin esta funcionalidad.

Un recurso tradicional toma como parámetro un dato en la ruta,

por ejemplo, un ID de producto, para cargarlo.

Si el usuario permanece en el mismo componente,

pero navega hacia otro ID de producto,

el recurso cambiaría inmediatamente su estado

y la interfaz parpadearía durante la navegación.

Esto provocaría efectos visuales molestos,

sobre todo si un guard cancela la navegación

y el ID debe regresar a su valor inicial.

Con este nuevo comportamiento, esto ya no sucederá.

La descripción del pull request aclara

que no está expuesto aún para uso público,

pero es claramente el primer paso para hacer

que resource y router trabajen juntos.

Para terminar, la adopción de micro-frontends sigue siendo

una decisión arquitectónica común en entornos empresariales.

Aunque no sea una característica nativa del framework Angular,

existen dos soluciones populares en la comunidad,

Native Federation y Module Federation.

La diferencia principal en Angular

es que Native Federation funciona con esbuild,

el builder moderno de Angular,

mientras que Module Federation trabaja tradicionalmente

con el antiguo Webpack o alternativas como Rspack.

Native Federation está mantenido por Angular Architects y el soporte

de Module Federation en Nx ha sido

el estándar habitual en estos espacios de trabajo.

Sin embargo, en la publicación de lanzamiento de Nx 23,

el equipo ahora recomienda oficialmente

el paquete Native Federation de Angular Architects

para Angular, marcando como obsoletos los generadores

y ejecutores específicos de Module Federation anteriores dentro de Nx.
